# Sparse full-population bipartite community optimization

## Status and scope

`sparse_optimizer.py` implements **sparse monotone bipartite modularity ascent with mutual-best agglomeration and connected-component refinement**, version `sparse-barber-monotone-1.1.2`. This is a separately specified heuristic, not a claim to have reproduced Beckett's LPAwb+, Leiden, or an exact global optimum. Importing the module does not read data or start a run. Computational feasibility on the full dataset requires measured benchmarks.

Version 1.1.1 adds an explicit rejection of numerically unsupported reciprocal normalizers (for example, synthetic subnormal totals near 1e-320). This does not change kernels or the optimization trajectory for ordinary supported amounts; regression tests compare it exactly with archived version 1.1. Every saved run records its actual code hash and version. Earlier quarter and initial full-network benchmarks retain their frozen version-1.1 code snapshots.

Every supplied wallet, event and positive weighted link is used. No rank, activity, amount or community-count cutoff is imposed. The caller must supply matching CSR (wallet rows) and CSC (event rows) arrays and verify their exact correspondence. The routine checks shapes, bounds and positive finite weights when `validate=True`; it does not independently prove that the two orientations contain identical links. Zero-strength declared nodes are retained but have no data-informed membership. Modularity of an entirely zero-weight graph is undefined; the optimizer returns `Q=None` with an explicit status.

## Scientific objective

Let A_ue be the aggregated positive participation amount from wallet u in event e. Let s_u=sum_e A_ue, t_e=sum_u A_ue and M=sum_ue A_ue. Wallet and event labels share one community namespace. The objective is

Q_gamma = sum_c [m_c/M - gamma S_c T_c/M^2],

where m_c sums A_ue over within-community links, S_c sums wallet strengths and T_c sums event strengths. Gamma=1 is the weighted Barber strength-product baseline. No one-mode projection is constructed. A high optimized Q is not a p-value or evidence, by itself, of statistically significant or substantively meaningful communities.

Two separate estimands are supported:

- `amount`: A is the observed amount matrix.
- `wallet_share`: P_ue=A_ue/s_u for each positive-strength wallet. Every such wallet contributes total weight one. The same weighted bipartite formula is applied to P, with its own column strengths and M equal to the positive-strength wallet count.

Normalization is calculated when an edge is visited, including during CSC traversal; the stored raw weights are not changed or duplicated. It changes the estimand but does not remove wallets, events or links. The objective is based on Barber (2007) and its weighted form discussed by Beckett (2016): [Barber](https://doi.org/10.1103/PhysRevE.76.066102), [Beckett](https://pmc.ncbi.nlm.nih.gov/articles/PMC4736915/).

Version 1.1.2 caches the scalar float64 factor `(1/M)/s_u` once per positive-strength wallet for node-move and merger scans. The same division, multiplication and summation order are retained; stored edges and optimization rules are unchanged. This is an arithmetic cache, not a new normalization or algorithm. It adds 8 bytes per wallet (24,852,112 bytes for 3,106,514 wallets) in `wallet_share` mode, and no cache in `amount` mode. The optional private-kernel cache argument defaults to the legacy calculation for independent comparisons. All 33 independent tests passed on the cached version; these include bitwise scalar-factor, direct move/merge-state and complete-trajectory comparisons against archived version 1.1.1 for both modes, multiple seeds and weight scales. The machine-readable record is `sparse_method_tests_v112.json`. Runtime improvements must still be measured, not assumed. Trajectory comparisons require matched update budgets without a binding wall-clock limit: a faster implementation can execute more updates before a time cap, so time-limited endpoints need not be identical.

## Fully specified search

1. Start with a distinct singleton label for every declared node. A seeded permutation assigns label IDs, which also supplies reproducible tie priorities. Alternatively, accept complete supplied memberships for continued optimization. No target cluster count is selected.
2. Sweep wallets, then events, visiting a seeded random permutation of each side. For a wallet u, the score of group c is A(u,c)/M - gamma (s_u/M)(T_c/M); for an event exchange wallet and event roles. Move only if the best score strictly exceeds the current score by the numerical criterion below. Keep the present group on an exact best-score tie; other exact ties use the lowest seeded label ID.
3. Candidate groups are adjacent groups, the current group and a free singleton. This is complete for a one-node improvement with nonnegative weights and gamma>=0: every nonadjacent group's score is nonpositive; the free singleton has score zero. Empty labels are recycled without limiting group count. Supplied isolates remain at their initial labels.
4. Repeat sweeps until one complete sweep makes no moves. With `connectivity_refinement=True` (default), split each group into connected components of its induced observed bipartite graph. This preserves its total observed internal weight while removing nonnegative strength-product penalties between components, so Q cannot decrease for gamma>=0. No graph edge or node is removed. If any group splits, recompute Q, log the operation, and repeat node sweeps. After a zero-move sweep with no split, consider group mergers. For groups c,d, the exact improvement is

   delta Q = [W(c,d)+W(d,c)]/M - gamma [S_c T_d + S_d T_c]/M^2.

   W(c,d) sums links from wallets in c to events in d. Only pairs with observed cross-links can have positive improvement. For each group, scan its member nodes' incident edges and accumulate cross-weight in reusable one-dimensional arrays. Choose its best strictly positive partner, breaking exact ties by lowest label ID. Merge disjoint mutually best pairs simultaneously. Their improvements are additive because no pair shares a group.
5. After mergers, repeat node sweeps. Convergence is reported only following a complete zero-move sweep, no component splits (when enabled), and a complete merger scan finding no positive candidate. A time, sweep or merger-round cap is reported as a bounded stop, never convergence. Positive candidates without a mutual pair are reported as a stall, not convergence.

The normalized single-node delta is (new_edge_mass-old_edge_mass)/M - gamma(s_u/M)(T_new-T_old)/M. This formula and the merger formula are public reference helpers for independent testing. The implementation uses float64 and recomputes Q from all CSR edges after each complete or interrupted sweep and each merger round. It raises an error for a recomputed decrease exceeding 1e-10*max(1,abs(Q_before),abs(Q_after)). Smaller differences can reflect rounding; they are still recorded.

The default move/merge tolerance is relative, 1e-12 times the largest local positive-edge/null contribution involved. It is **not** an absolute Q improvement threshold: a small wallet's contribution is not suppressed merely because its absolute global weight is small. Community strengths use two-part Neumaier accumulators, including subtraction when a node moves; separate wallet/event node counts reset a side's strength exactly when its last member leaves. Cross-weight tallies are also compensated. These safeguards reduce cancellation when large and small wallets share a group, but float64 is not exact arithmetic. Zero-gain moves are not performed. This can prevent crossing flat objective plateaus and differs from algorithms that permit neutral moves.

## Relationship to the published algorithm

Beckett's LPAwb+ alternates label updates with modularity-improving agglomeration and initializes distinct labels on the smaller bipartite side. Its published implementation also uses randomly selected equal-score labels. We inspected the [official R implementation](https://github.com/sjbeckett/weighted-modularity-LPAwbPLUS/blob/master/code/R/LPA_wb_plus.R), archived as [Zenodo 34055](https://doi.org/10.5281/zenodo.34055). Our all-node singleton initialization, empty-label moves, neutral-move prohibition, batched mutually best mergers and stopping rules are explicit differences. Therefore results must name this implementation rather than label it LPAwb+ or DIRTLPAwb+. The objective is established; this particular implementation is a computational heuristic whose numerical behavior and sensitivity require validation.

## Memory, execution and limitations

CSR and CSC store each raw edge twice: int32 neighbor IDs and float64 values, with int64 pointers. At 255,704,359 links and 3,870,892 active nodes, those arrays occupy about 5.744 GiB before allocator, input, operating-system and optimizer overhead. Extra optimizer state is O(number of nodes), not a dense wallet-by-event, event-by-event or community-by-community matrix. No global edge-pair dictionary or Python edge-tuple list is built. The agglomeration scan visits incident edges from both sides; it does not enumerate all community pairs.

Input arrays may be read-only memory maps. Node sweeps and merger scans are batched; callbacks provide progress metadata. Wall-clock limits are checked between compiled batches/stages, not inside one very high-degree node or a full objective scan. Initial compilation, input validation and strength construction count toward elapsed time but are not interruptible at every row. Resume memberships preserve the population and continue ascent, but the RNG trajectory is not an exact restart of an uninterrupted run.

The returned `converged` status concerns only the tested one-node and pair-merge neighborhood at the stated tolerance, plus the component refinement when enabled. It is not proof of a global optimum, seed stability, statistical significance or a unique partition. Moving a node can disconnect the group it leaves. A converged run with refinement enabled has passed the connected-component check; a budget-limited run may not have, and `connected_communities_guaranteed` remains false. Independent connectedness diagnostics are still required before interpretation. Modularity resolution effects, optimization variability, identity ambiguity of wallet addresses and unequal temporal opportunities remain. Communities in pooled history may reflect event lifetimes as well as subject preference. Categories are annotations, not definitions of the detected communities.

Before reporting scientific findings: independently test objective and move/merge deltas; inspect monotonicity and stopping status; compare seeds and weight estimands; measure actual peak memory/time; diagnose connectedness; and compare against a defined null if making a significance claim. A successful synthetic or quarterly benchmark is not a completed full-history analysis.
